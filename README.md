# 선생님, 잠깐만요! — 어쩌다 담임

신규 고등학교 교사의 3주를 그린 픽셀아트 업무·스토리 시뮬레이션입니다. DAY 1~15의 수업·서류·채점·방송·출결·상담·시험 업무를 전용 작업 화면에서 처리합니다. 시간제한은 없으며, 실수는 근거를 다시 확인해 고칠 수 있습니다. 미확인 사유와 공동 검토도 절차대로 기록하면 당일 업무를 마칠 수 있습니다.

[배포된 게임](https://progh2.github.io/ssamplease/) · [게임성 검토와 개선 기록](docs/GAMEPLAY_REVIEW.md)

## 실행

```bash
npm install
npm run dev
```

검증은 `npm test`와 `npm run build`로 수행합니다. 진행 상태와 언어는 브라우저 localStorage에 자동 저장됩니다.

브라우저 테스트:

```bash
npx playwright install chromium
npm run test:e2e
```

PC와 모바일 Chromium에서 첫 3일 연속 진행, 8개 수업, 후기 채점, 3일 시험 감독, 출결, 상담 약속의 후속 대화, 기안 예산·보완·공문 연속성, 자료 분류, 오류 재시도와 저장 복원을 검사합니다. 테스트는 로컬 서버를 자동 실행합니다. `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`로 기존 Chromium 경로를 지정할 수 있습니다.

저장 버전이 달라져도 알려진 업무 완료 기록을 복원합니다. 과거 버전이 이전 날짜 기록을 버린 경우, 해당 날짜를 통과했다는 사실로 필수 업무 처리 여부만 복원하며 대화 선택은 추정하지 않습니다. 저장소 접근 실패 시 경고를 표시하고 현재 세션은 메모리에서 계속 진행합니다. 작업 중 저장되는 항목은 아래 플레이 범위에 명시되어 있습니다.

## 현재 플레이 범위

업무 시작 버튼은 해당 업무만 표시하는 전용 화면을 엽니다. 반투명 할 일 보드는 내부 스크롤과 접기를 지원하며, 장면 높이에 영향을 주지 않습니다. 빈 책상·교실·방송실은 생성한 픽셀아트 배경입니다. 교무실 전체 배치는 실제 사진을 받은 뒤 작업합니다.

- 수업: 시연/짝 활동 선택 → 날짜별 순서·조건·반복·자료 처리 문제 → 예제 실행 → 학생의 새 상황 설명 → 수업 기록.
- 문서: 명부·서명·동의 여부 대조 → 실제 불일치 항목 표시 → 접수/보완. 비동의는 유효한 선택으로 접수.
- 채점: 학생 3명씩 기준별 점수·근거·피드백 → 판독 불가 원본은 공동 검토 → 다음 수업 메모와 후속 수업 활동.
- 방송: 부품별 시험 → 원인 진단 → 신호 연결·예비 케이블 교체·출력 레벨 시험 → 구매 기안.
- 전화(DAY 7): 주소록 선택 → 연락 시도 → 응답 없음 기록 → 출결 확인 중 처리 연결.
- 출결: 추가 확인 3명과 근거 문서 대조 → 출석·지각·승인 활동·질병·확인 중 분류 → 28명 합계와 후속 사유 보완.
- 상담: 학생 이야기·점검 근거·바람 확인 → 리허설/동료/휴식 계획 → 14일 차 약속별 후속 대화.
- 행정: 구매 수량·예산·결재선·근거 → 같은 규격 견적 비교 후 보완 → 승인 메시지 → 기존 수량의 시행 공문 작성·검토.
- 시험 감독: 변경 교실 확인 → 좌석 관찰 → 관련 지침 → 사건별 조치·기록 → 수량과 인계 사항 대조.
- 시험 자료: 일정 카드·배부 묶음·원본 자료 분류와 봉입. OMR은 기본 확인→성명 누락→학번 누락으로 변칙을 추가합니다. 실제 OCR/OMR 판독 기능은 아닙니다.

모든 작업의 주요 판단·배치·작성 입력은 작업 중에도 자동 저장되어 새로고침 후 업무를 다시 열면 복원됩니다. 수업과 감독은 교실에 다시 입장해야 합니다. 완료한 업무의 선택은 별도 `memories`에 보관해 날짜가 바뀌어도 다음 이야기에서 사용합니다. 저장 버전 8은 이전 완료 기록을 유지하지만 구형 단순 채점·수업의 미완료 입력은 새 작업 시작으로 돌아갈 수 있습니다. 오류 안내 자체는 일시적입니다.

책상에는 컴퓨터부터 시작해 업무 진행에 따라 서류·빨간 펜·방송 장비·출석부·전화기가 고정 위치에 등장합니다. 물건을 누르면 진행 가능한 해당 업무가 열리고, 완료 후에도 물건은 남습니다. 책상 물건 SVG는 아직 임시 에셋입니다. 배경과 방송반 학생 초상화의 저장 경로·생성 프롬프트는 [배경 기록](docs/PIXEL_ART.md)과 [게임플레이 아트 기록](docs/GAMEPLAY_ART.md)에 있습니다.

- DAY 1: 핫메신저 확인, 가정통신문, 첫 수업
- DAY 2: 서명 누락 변칙, 수업, 기본 채점
- DAY 3: 업무 요청, 부분점수 채점, 수업
- DAY 4: 방송반 담당 요청, 장비 점검
- DAY 5: 신호 연결 퍼즐, 에듀그렛 구매 요청
- DAY 6: 담임 부재, 임시 담임 기본 출결
- DAY 7: 사유 미확인 결석의 확인 중 처리, 기안 보완 요청
- DAY 8: 출결 후속 반영과 방송반 학생 상담
- DAY 9: 구매 요청 승인과 반복 채점 검토
- DAY 10: 시험 감독표 확인과 시험 자료 봉입
- DAY 11~13: 시험 감독 반복, 교실 변경, 학생 질문, OMR 누락 변칙
- DAY 14~15: 시험 후 채점·상담·행정 마무리와 3주 완주 엔딩
- `completed`와 `resolved_with_issue`를 모두 처리 완료로 인정
- 한/영 전환 구조(기존 이야기 영어 번역은 일부 미완료), 반응형 레이아웃, Phaser 교무실·교실 장면
- 수업은 시간표의 다음 수업 교실로 이동해야 완료 가능
- 에듀그렛에서 기존 수량과 제출 → 보완 → 재제출 → 승인 → 집행 상태 확인
- 예산 초과 시 수량 수정, 보완 요청 시 비교 견적 첨부 후 재제출

## 콘텐츠 확장

날짜와 업무는 `src/content/days.ts`, 선행 조건은 `dependencies.json`, 교시·교실은 `timetables.json`에 정의합니다. 수업 `lessons.json`, 서류 `exercises.json`, 채점 `grading.json`, 출결 `attendance.json`, 상담 `counseling.json`, 감독 `supervision.json`, 자료 분류 `examDesk.json`은 같은 디렉터리의 독립 데이터입니다. 같은 유형의 새 시나리오는 해당 JSON과 날짜 업무를 연결해 추가합니다. 새로운 유형은 전용 React 컴포넌트를 추가하고 App에 연결합니다.

`npm test`는 참조·의존성 순환·교시 충돌, 판단 규칙, 상태 복원, 전용 화면의 업무 범위를 검사합니다. `npm run validate:content`는 기본 날짜 데이터 검증만 실행합니다. 기존 UI 문자열은 `src/i18n.ts`, 업무 흐름 번역은 `src/locales/flow.json`, 새 시나리오의 한/영 문자열은 해당 JSON에 있습니다. 챕터 전체 JSON 분리와 기존 이야기의 영어 번역 완성은 후속 작업입니다.

## 프로젝트 진행

우선순위와 마일스톤은 [docs/ISSUES.md](docs/ISSUES.md)에 정리되어 있습니다. GitHub 인증과 저장소 생성 후 아래 명령으로 초기 이슈를 등록할 수 있습니다.

```bash
gh label create P0 --color B60205
gh label create P1 --color D93F0B
gh label create P2 --color FBCA04
gh label create feature --color 1D76DB
gh label create content --color 7057FF
bash scripts/create-issues.sh OWNER/REPO --dry-run
bash scripts/create-issues.sh OWNER/REPO
```

`main`에 push하면 `.github/workflows/deploy.yml`이 테스트와 빌드 후 GitHub Pages로 배포합니다. 저장소 Settings → Pages → Source는 **GitHub Actions**로 설정합니다.
